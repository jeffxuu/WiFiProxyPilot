## Основные возможности

- Определяет подключённую сеть и сопоставляет полный SSID без учёта регистра.
- Находит **шлюз IPv4 по умолчанию** текущего физического Wi-Fi-интерфейса и применяет выбранный порт прокси; по умолчанию `7890`.
- Использует правила прямого подключения для выбранных сетей. В новой установке **нет предустановленных правил Wi-Fi**; любое правило можно изменить или удалить.
- Предлагает интерфейс WPF в духе macOS, светлую/тёмную темы и системный трей с независимым фоновым наблюдателем — watcher.
- Разделяет автоматическое управление, состояние ручного прокси Windows и необязательную TCP/HTTP-диагностику. Включённый прокси не доказывает наличие доступа в интернет.
- Сохраняет конфигурацию атомарно и различает «сохранено» и «применено наблюдателем».
- Хранит исходную резервную копию прокси и защищает последующие изменения пользователя или другого приложения.
- Предоставляет исходный код под MIT для проверки и совместной разработки.

Опубликованный v3.0.0 содержит прежний интерфейс и поведение, **без** показанного выше интерфейса WPF v3.2. v3.1.0 — Draft Prerelease; опубликованного релиза v3.2 пока нет. Артефакты сборки требуют доступа к репозиторию и имеют срок хранения. Черновики не являются публичными загрузками. Перед установкой проверьте версию, описание релиза и SHA256. Значок Release отражает опубликованные версии, а не версию разработки.

Целевая платформа — **Windows 11 x64**, Windows PowerShell 5.1, служба WLAN и Windows Script Host. Автономная EXE не требует отдельной установки .NET, Python, Node.js или WebView2. Совместимость с другими версиями Windows не заявлена. Политики организации могут ограничить получение данных WLAN, изменение прокси или планировщик задач. Текущие сборки не подписаны; оставляйте защиту Windows включённой.

Скачайте EXE либо распакуйте ZIP и сравните хеш с `SHA256.txt`:

```powershell
Get-FileHash .\WiFiProxySwitcher.exe -Algorithm SHA256
```

Для совместимости обновления файл по-прежнему называется `WiFiProxySwitcher.exe`. Запускайте его от своего обычного интерактивного пользователя Windows. Одно открытие окна v3.2 не включает управление прокси. Не устанавливайте приложение для повседневной учётной записи от имени другого администратора.

## Быстрый старт и первая настройка

1. **Загрузите** сборку и проверьте её версию и хеш.
2. **Настройте** порт существующего прокси на шлюзе Wi-Fi и добавьте имена сетей для прямого подключения.
3. **Включите автоматическое переключение**, предварительно проверив настройки, которыми будет управлять приложение.

**На шлюзе действительно должен работать прокси-сервис. WiFi Proxy Pilot не предоставляет прокси-сервер или VPN-узлы.** Для Android-точки доступа приложение определяет текущий шлюз IPv4. Укажите порт отдельного прокси-приложения и разрешите ему принимать подключения от Windows-устройства. Сама по себе точка доступа не является прокси.

## Принцип работы

```text
Wi-Fi подключён → Прочитать стабильные данные SSID/интерфейса → Проверить правила
  ├─ Найдено правило прямого подключения → Отключить ручной прокси Windows
  └─ Правила нет → Определить шлюз IPv4 текущей сети Wi-Fi
                   → Применить адрес шлюза + настроенный порт
```

Перед изменением наблюдатель проверяет текущую сеть, чтобы после смены Wi-Fi не использовать старый шлюз. При неизвестном SSID, отсутствии маршрутов или неоднозначных интерфейсах текущие настройки сохраняются, показывается причина и выполняется повторная проверка. Подтверждённое отключение Wi-Fi выключает ручной прокси. Значения PAC и автоматического обнаружения сохраняются и могут по-прежнему влиять на маршрутизацию приложений.

## Управление правилами Wi-Fi

В **Wi-Fi Rules** можно добавлять, переименовывать и удалять правила, а также добавлять надёжно определённую текущую сеть. Пустой список допустим. Сопоставляется полное имя через `OrdinalIgnoreCase`, не префикс и не подстрока. Допустимые пробелы сохраняются; имя должно занимать 1–32 байта UTF-8 и не содержать управляющих символов.

**Save and Apply** проверяет параллельные правки и записывает файл атомарно. «Сохранено» подтверждает запись. Для «Применено» нужен свежий совместимый heartbeat наблюдателя с той же ревизией и стабильная сеть. Иначе приложение показывает ожидание фонового применения. Отмена отбрасывает несохранённые правки; удалённые правила не восстанавливаются без вашего участия.

## Системный трей и режимы прокси

| Действие | Результат |
| --- | --- |
| Включить автоматическое переключение | Повторно определить сеть и управлять ручным прокси по правилам |
| Пауза | Остановить автоматические изменения; текущий прокси остаётся настроенным |
| Прямое подключение | Приостановить управление и отключить только ручной прокси Windows |
| Проверить сейчас | Запросить новое наблюдение сети и стабильную оценку |
| Закрыть окно | По умолчанию скрыть в трей; наблюдатель продолжает работу |
| Выйти из интерфейса | Закрыть GUI и трей; независимый наблюдатель продолжает работу |
| Восстановить исходную конфигурацию | Остановить управление и восстановить копию с проверкой конфликтов |

Пауза и намерение использовать прямое подключение сохраняются после перезапуска GUI и входа в Windows. Автозапуск наблюдателя при входе и автозапуск трея настраиваются отдельно.

**Strict** применяет выбранное правило и сообщает ошибки диагностики, не отключая прокси молча. **Safe** может перейти к прямому подключению после заданного числа последовательных диагностических ошибок; часть трафика при этом может обойти прокси. Неизвестный результат диагностики не считается восстановлением. TCP проверяет лишь возможность подключения к порту. HTTP отправляет реальный запрос через прокси к вашей тестовой HTTP-URL. Ни одна проверка не гарантирует работу всех сайтов и программ.

## Восстановление и удаление

Исходная резервная копия ручного прокси находится в `state/proxy-before-install.json` внутри каталога установки. Обновление сохраняет её и ваши правила, не создавая новую «исходную» копию. При изменении конфигурации сохраняется предыдущий корректный файл. Не публикуйте эти локальные файлы.

При существующей установке откройте новую EXE и выберите **Settings → Advanced operations → Repair installation / Upgrade**. Не удаляйте приложение заранее и не заменяйте свою конфигурацию стандартной из репозитория. См. [миграцию конфигурации](docs/CONFIG_MIGRATION.md).

Используйте **Restore original configuration**, **Settings → Advanced operations → Uninstall** или список установленных приложений Windows. Восстановление и удаление сравнивают текущие настройки с исходными и последними записанными этим инструментом. Более поздние внешние правки вызывают конфликт, а не перезаписываются. Принудительное восстановление требует явного выбора; удаление также может сохранить текущий прокси. Удаляются только принадлежащие приложению задачи/записи автозапуска и проверенные файлы продукта, с защитой посторонних и изменённых пользователем файлов. Прямой режим сохраняет исходную копию.

## Безопасность и конфиденциальность

- SSID, настройки прокси, состояние и журналы обрабатываются локально; облачная учётная запись и аналитический сервис не требуются.
- Программа не собирает пароли Wi-Fi. Необязательная диагностика подключается к выбранному прокси, а в режиме HTTP — к указанной вами URL.
- Исходная копия сохраняется. Установка и работа с задачами учитывают личность текущего пользователя и проверяют разрешения.
- Изменяется **ручной прокси** текущего пользователя Windows. DNS, маршруты и правила брандмауэра не меняются.
- Журналы и диагностика могут содержать идентификаторы сети. Перед передачей проверьте их и удалите частные сведения.

В исторических коммитах и материалах старых релизов есть прежние примеры сетей и пути машин. Статус Private не удаляет эти данные. До публикации владелец должен отдельно рассмотреть [аудит публичного репозитория](docs/PUBLIC_REPOSITORY_AUDIT.md). Сообщайте об уязвимостях по [SECURITY.md](SECURITY.md).

## Частые вопросы

**Как автоматически переключать прокси по Wi-Fi в Windows 11?** Укажите порт прокси шлюза, добавьте SSID для прямого подключения и включите автопереключение. Наблюдатель оценивает стабильные смены сети и меняет ручной прокси текущего пользователя.

**Как использовать шлюз Android-точки доступа как прокси Windows?** Запустите на телефоне отдельный прокси, разрешите доступ подключённых устройств и укажите порт. Шлюз определяется по текущему Wi-Fi-интерфейсу. Если подключения нет, проверьте сервис и брандмауэр телефона.

**Есть ли здесь VPN?** Нет. Сервис предоставляете вы. Приложения с собственными настройками прокси или не использующие настройки Windows могут вести себя иначе.

**Почему прокси включён, а интернет не работает?** На шлюзе может не быть прокси; порт может быть неверным, сервис остановлен либо целевой сайт недоступен. Проверяйте TCP и HTTP отдельно. Пауза сохраняет настройки, прямой режим отключает ручной прокси. PAC всё ещё может влиять на трафик.

**Как обходить прокси в отдельных сетях Wi-Fi?** Добавьте полные SSID в Wi-Fi Rules и сохраните/примените. Все правила изменяемы и удаляемы; пустой список разрешён.

**Как вернуть настройки Windows?** Выберите восстановление исходной конфигурации и проверьте конфликт внешних изменений. Прямой режим только отключает ручной прокси; исходный сервер и список исключений он не восстанавливает.

**Продолжает ли программа работать после закрытия окна?** Да. X обычно скрывает окно в трей. Даже выход из GUI оставляет независимый наблюдатель работающим. Используйте паузу или восстановление для изменения фонового управления.

**Почему текущая сеть не определяется?** Причиной могут быть разрешения WLAN/местоположения, политики организации, отсутствие маршрутов, остановленный наблюдатель или старый heartbeat. Интерфейс показывает причину и последнее корректное наблюдение, не выдавая старые данные за текущие.

**Что проверено тестами?** См. [результаты v3.2](docs/TEST_RESULTS_V3_2.md), [измерения производительности](docs/PERFORMANCE_V3_2.md) и [контрольный список релиза](docs/RELEASE_CHECKLIST.md). Изолированные тесты не равны приёмке реальной сети/установки; целевые показатели производительности не являются измеренными результатами.
