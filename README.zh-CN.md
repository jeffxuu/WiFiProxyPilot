# WiFi Proxy Pilot · Wi-Fi 智能代理助手

[English](README.md)

根据你自己管理的 Wi-Fi 规则，自动切换 Windows **手动代理**。连接手机热点时使用当前无线接口的 IPv4 默认网关和指定端口；选定网络直连；日常从系统托盘管理。

**本工具不自带 VPN 或代理服务器。** 网关和端口上必须已有代理服务。系统代理开启不代表代理服务或互联网已经可用。

v3.2.0-beta.1 正在开发。当前先准备实际 WPF 界面供设计确认，发布材料仍是草稿。真实 Wi-Fi、代理写入、安装升级、登录、休眠恢复和卸载需要授权后在 Windows 验收。实际范围见[测试结果](docs/TEST_RESULTS_V3_2.md)和[发布检查](docs/RELEASE_CHECKLIST.md)。

## 核心功能

- 读取当前物理 Wi-Fi 接口的 IPv4 默认网关，结合用户端口；切网后重新确认，避免混用旧网关。
- 所有免代理规则都能添加、编辑、删除。新用户默认空名单，完整名称忽略大小写匹配。
- 自动管理、暂停、直连、Windows 代理实际状态与 TCP/HTTP 诊断分开展示。
- WPF 界面采用简洁 macOS 层级和自定义控件模板，适配 Windows 操作习惯；保留系统托盘、单实例及独立 Watcher。
- 原子保存、编辑冲突保护和后台应用确认；保存成功与规则生效分别显示。
- 保留安装前代理备份，恢复时保护用户或其他软件后续修改。

界面当前使用简体中文；本项目同时提供英文说明，不宣称已实现完整英文界面。详细实现与验收状态以链接文档为准。

## 下载和兼容性

候选构建和草稿位于现有 [WiFi-test Releases](https://github.com/jeffxuu/WiFi-test/releases) 与 [Windows 构建工作流](https://github.com/jeffxuu/WiFi-test/actions)。仓库目前为 Private，需要仓库访问权限。v3.1 草稿是旧版，不能作为 v3.2 下载；请以最终候选发布说明的构建和 SHA256 为准，当前不宣称已有 v3.2 公开下载。

Windows x64 自包含 EXE 保留兼容文件名 `WiFiProxySwitcher.exe`，无需另外安装 .NET、Python、Node.js 或 WebView2。需要 Windows 11、系统自带 Windows PowerShell 5.1、WLAN 服务和 Windows Script Host。组织策略可能限制代理或任务修改。未签名构建会注明，不要求关闭或绕过系统安全功能。

下载 EXE 或 ZIP 及对应 `SHA256.txt`，验证文件：

```powershell
Get-FileHash .\WiFiProxySwitcher.exe -Algorithm SHA256
```

## 首次配置

1. 打开 EXE。仅打开界面不修改代理。
2. 阅读作用说明：工具管理 Windows 手动代理，不提供代理服务。
3. 配置当前 Wi-Fi 网关上的代理端口，通常为 `7890`；默认网关不一定有代理服务。
4. 添加需要直连的 Wi-Fi 名称，也可以暂不添加。网络名称能可靠读取时可从当前连接添加。
5. 确认即将修改的 Windows 手动代理设置，明确开启后才安装/启用自动切换。

安装属于当前交互用户，不要换成另一管理员账户为日常账户安装。旧用户打开候选版本后，在设置的高级操作中修复安装/升级；不要先卸载或用默认配置覆盖已有名单和最初备份。详见[配置迁移](docs/CONFIG_MIGRATION.md)。

## Wi-Fi 规则管理

![实际运行的 Wi-Fi 规则编辑器，使用模拟数据](docs/images/rules.png)

*真实规则编辑器截图，来自隔离测试环境。*

进入“Wi-Fi 规则”添加网络、编辑名称、删除或从当前连接添加。合法空格原样保留；名称必须为 1–32 个 UTF-8 字节且不含控制字符。名称子串、前后缀不匹配。

“保存并应用”先检查冲突，再原子写入。“已保存”只代表文件写入；兼容 Watcher 确认相同 revision 且当前网络稳定后才显示“规则已应用”。无法确认时显示“已保存，等待后台应用”。取消可放弃未保存修改。空名单合法，后台不会重新添加隐藏规则。

## 托盘与常用操作

| 操作 | 结果 |
| --- | --- |
| 开启自动切换 | 重新确认当前网络，按用户规则管理代理 |
| 暂停自动切换 | 停止后台代理写入；当前代理保留，可能继续生效 |
| 恢复直连 | 暂停自动管理，仅关闭 Windows 手动代理 |
| 立即检测 | 请求重新采集网络，经稳定确认后处理 |
| X 关闭窗口 | 默认隐藏，托盘和 Watcher 继续 |
| 退出界面 | GUI/托盘退出，独立 Watcher 继续 |
| 恢复安装前配置 | 停止自动管理，按最初备份与冲突保护安全恢复 |

暂停和直连意图跨 GUI 启动、登录和重启保留。Watcher 登录运行和托盘自启分别配置。PAC 与自动检测保持现状，仍可能影响应用实际选路。

## 代理策略和诊断

**Strict** 在用户开启后按规则配置代理；探测失败时提示原因，不偷偷关闭代理。**Safe** 根据有效诊断及连续失败阈值回退直连，因此部分流量可能不经过代理。未知诊断不算代理恢复成功。

TCP 可达只代表端口能够连接；HTTP 验证必须执行真实的代理请求，并设置 HTTP 诊断 URL。两者都不等于全面互联网连通保证。无无线网卡、SSID 权限受限、IPv4 网关未就绪、多接口歧义等情况保留原有保护行为，并显示原因和建议。

## 备份、恢复和卸载

安装前手动代理保存在安装目录的 `state/proxy-before-install.json`，升级不重复生成。配置编辑保留上一份有效文件。不要用仓库默认值覆盖，也不要直接对外分享含隐私的备份。

恢复直连保留最初备份。恢复安装前配置和卸载比较当前配置与原始/最后自身写入配置；遇到用户或其他程序后续修改时默认拒绝覆盖，显示冲突。强制恢复需要明确选择，卸载也可选择保留当前代理。

使用设置 → 高级操作 → 卸载，或 Windows 已安装应用入口。只清理自有任务、启动项和通过清单/哈希核查的产品文件；无关文件和用户改过的文件受到保护。更多细节见[迁移说明](docs/CONFIG_MIGRATION.md)。

## 常见问题

**代理开启了，为什么仍无法联网？** 代理服务可能没启动、端口有误或当前网关没有代理。查看独立诊断，必要时暂停或恢复直连。

**关闭窗口会停止代理吗？** 默认 X 仅隐藏；退出托盘界面也不停止独立 Watcher，不自动恢复代理。

**能删除全部规则吗？** 可以。每条规则都由用户管理，空名单受支持。

**为什么状态“暂时无法读取”？** WLAN/位置权限、组织策略、后台停止或过期心跳都可能影响可靠读取。界面显示原因及上次成功时间，不把旧数据当作实时状态。

**是否影响所有应用？** 工具管理当前用户的 Windows 手动代理。自带代理、忽略系统代理或使用 PAC 的应用可能行为不同。

**哪些行为已经验收？** [测试结果](docs/TEST_RESULTS_V3_2.md)区分隔离模拟与真实 Windows 验收；[性能报告](docs/PERFORMANCE_V3_2.md)保留实际样本和限制，目标时间不是测试结果。

## 技术架构和构建

WPF/MVVM 展示层调用应用服务。沿用现有 PowerShell 控制/生命周期、原生 WLAN/WinINet、原子配置、完整 SHA256 资源缓存、任务所有权及恢复保护。UI 与后台引擎版本分别识别。安装身份继续使用 `WiFiProxySwitcher` 以保证兼容。

使用固定的 .NET 8 SDK 和 Windows PowerShell：

```powershell
powershell.exe -NoProfile -File tests\Run-Tests.ps1 -ResultPath artifacts\engine-results.json
powershell.exe -NoProfile -File release\Build.ps1
```

构建脚本打包校验资源、运行 C# 检查并发布 Windows EXE；不安装或修改本机代理。见[贡献说明](CONTRIBUTING.md)、[产品要求](docs/PRODUCT_REQUIREMENTS.md)、[状态模型](docs/INTERACTION_STATE_MACHINE.md)。
