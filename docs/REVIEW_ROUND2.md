## 发现的问题、原因、影响与修改

| ID | 原因及影响 | 实际修改与回归证据 |
|---|---|---|
| B01 | Start 持有 Watcher 锁时启动任务；新进程可能立即把父进程的锁误判为重复实例，正常退出且不触发重启 | 启动前释放检测锁，依靠真正 Watcher 的生命周期锁防重；生产 Start 函数模拟 50 次调用，只有一次任务启动，并断言调度时锁未持有 |
| B02 | Start 发现已有监控后直接返回，可能留下禁用的登录任务 | 返回前确保任务启用；同一启动回归检查 Enabled |
| B03 | SSID/WLAN 查询错误被转为 Unknown，但坏句柄没有重建；WLAN 服务恢复后仍可能使用失效句柄 | 快照明确携带 ReopenNative，监控重开；失败→新快照→成功应用回归 |
| B04 | 先读 SSID 后读路由可能拼出 A 的 SSID 与切换后 B 的数据 | WLAN 前后夹读，校验原始 SSID 身份与事件 Generation；写入前再次核对，丢弃变化快照 |
| B05 | 非 UTF-8 的实际 SSID 被当成读取失败，遗漏“其他任何 Wi-Fi” | 保留真实 SSID 字节和长度，UTF-8 无法解码时使用明确 raw SSID 十六进制标识，禁止该显示文本命中字符串白名单；原生解码函数测试 |
| B06 | 任一 NetTCPIP 查询异常会丢弃已知白名单 SSID，导致白名单不能关闭 | 将可靠 SSID 与路由就绪分开；白名单关闭，普通网络 Keep 并记录路由错误 |
| B07 | 虚拟 WLAN 会令整个快照失败；“本机 IP”只排除了同接口的 Preferred 地址 | 排除虚拟 WLAN 候选；排除所有接口的本机 IPv4 地址；真实+虚拟并存及 VPN 本机地址回归 |
| B08 | 仅看 API 值决定是否更新，忽略注册表已经漂移；关闭时可能重写 API 缓存中的旧地址 | 每轮比较 API 与注册表，写入返回经过验证的快照；关闭使用当前注册表地址/绕过，不回滚到旧缓存 |
| B09 | 注册表已等于安装前备份时，恢复直接返回，可能遗漏 WinINet 缓存和通知 | 仍执行恢复通知与双重回读；生产恢复函数注入测试验证不会跳过 |
| B10 | 无显式 SYSTEM/服务会话保护，错误身份运行可能触及服务账户 HKCU | 初始化拒绝 SYSTEM/LocalService/NetworkService 和 Session 0；用户 SID 与安装归属继续校验 |
| B11 | 第一次防抖轮次尚未应用 Strict 目标便执行诊断，慢端口会延迟设置 | 只有稳定确认并完成目标处理后才诊断；测试断言第一次 Probe 发生前已写入 |
| B12 | Safe 已因失败关闭后，一次 Unknown 会重新启用；长期暂停还可能复用旧诊断 | 已确认 Unavailable 保持到积极成功，Unknown 不证明恢复；事件/地址身份与长暂停使旧观测失效，重新确认 |
| B13 | HTTP 无 CRLF 的截断状态行或超长前缀可被判为成功 | 必须读到受长度与总时间限制的完整 CRLF 状态行；截断、LF-only、超长行均不得成功 |
| B14 | PollSeconds 可设 300，单次长等待使手动启动的监控很久无法响应 Stop | 等待拆成最多 500 ms 小段，每段检查停止；写入与诊断前也检查；300 秒配置的停止测试在 2 秒内完成 |
| B15 | 任务只核对名称/描述/用户，没有核对动作；可能启动或终止被改成其他程序的任务 | 校验执行文件、参数、工作目录、Interactive、Limited；接受旧版合法动作便于升级，拒绝被改动作 |
| B16 | Stop 先操作任务，任务权限失败时连停止标志都没写 | 先发本工具停止标志再管理任务；权限错误仍返回失败，原监控可收到停止请求 |
| B17 | 首次复制中途失败可留下无清单的非空目标，随后无法重复安装；重装验证了源配置却没有先验证实际保留的配置 | 首次安装在相邻暂存目录完成，再移动到目标；完整包、实际配置与任务冲突前置检查；失败注入验证目标不会半安装 |
| B18 | 重装重新计算用户 config 的归属哈希，卸载会把用户修改的配置当成工具原文件删除；升级可能覆盖改过的脚本 | 保留原 config 哈希；替换前将用户改过的脚本保存至 user-backups；新版本路径与未知文件冲突则拒绝覆盖 |
| B19 | 卸载先删清单/备份，再删注册表指针；后续失败会失去重试依据；清单错误可能在删了一部分文件后才发现 | 整体清单前置验证，持久化 Uninstalling 阶段，保留备份/清单直到相应步骤完成；支持源包 `-InstallDir` 恢复清理；多种中断回归 |
| B20 | 卸载删除整个安装注册表键，可能影响其他值/子键 | 仅删除本工具 InstallDir 值，键确实为空才删键；Windows 注册表调用需本机验证 |
| B21 | VBS Run 会展开命令字符串中的环境变量，用户路径直接插入可能被解释；静默早期异常可能无日志 | 在 CurrentDirectory 下用固定相对脚本名；初始化失败写独立有界控制日志；无法写日志时返回错误并输出 stderr，不伪称成功 |
| B22 | 启动心跳只按近期判断，可能复用旧文件；新回归又发现 DateTime 被隐式字符串化会丢失毫秒 | 启动前清理旧心跳，要求新 RunId 与本次时间，按 DateTime/DateTimeOffset/ISO 类型保留精度 |
| B23 | 防抖中间轮次成功会清空上次错误，持续写入异常可能重复刷日志 | 只有稳定目标成功才清除错误；统一失败日志限频及恢复记录，300 次失败循环验证 |
| B24 | 缺失/损坏的原备份没有在 Watcher 开始写入前检查；升级可能已停掉服务才发现问题 | 启动和升级前验证备份字段、类型与有效值；损坏备份拒绝后续写入，独立 Stop 仍可使用 |

Native.cs 同时清理部分查询失败时可能已分配的字符串，并在构造失败时释放已打开 WLAN 句柄/订阅。分配器和真实 API 失败路径属于静态审查修正，不能算作 Linux 上的 Windows API 复现。

## 本轮测试方式与边界

`tests/Run-Tests.ps1` 是唯一入口，包含原测试与 `Round2.Tests.ps1`。监控压力测试调用实际 `Invoke-MonitorCycle`，只替换网络、代理写入、日志输出等系统边界；生命周期测试调用实际安装/启动/恢复/卸载函数，文件操作真实执行，任务/ACL/注册表操作用明确测试替身。没有修改云端真实代理。

每项结果、错误与耗时在 `test-results.json`，汇总在 `TEST_RESULTS.md`。中途发现的失败没有删除断言；修复后重跑相关路径和完整套件。测试报告不把模拟任务或静态 WSH 检查当成真实 Windows 验证。

## 使用新版

解压新包，先运行 `tests\Run-Tests.bat` 和 `Diagnose.bat`。已有安装可从新包运行 `Install.bat`，会保留原始备份和已安装配置、更新本工具任务与代码，改过的脚本另存 user-backups。首次安装、Strict/Safe、静默入口与卸载选项见 README。

遇到中断卸载，可从完整源包运行 `Uninstall.bat -InstallDir "原安装目录"` 继续清理；恢复冲突用 `-ForceRestore` 或 `-KeepCurrentProxy` 明确选择。普通 `Uninstall.bat` 恢复原手动配置并移除专属任务，空目录、默认保留日志、用户修改和 user-backups 可以保留，不属于自启残留。
