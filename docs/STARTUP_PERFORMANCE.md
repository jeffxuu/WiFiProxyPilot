# 启动性能测量

环境：2026-10-13，Windows 11 Enterprise 10.0.26200，Intel Core Ultra 7 155H，22 逻辑处理器，约 15.47 GiB RAM。.NET SDK 8.0.425，自包含运行时 8.0.31。未禁用 Defender/企业安全软件，也没有独立测量其扫描影响。

所有启动验证使用隔离模拟网络，不调用真实代理或计划任务。冷启动定义为新的 .NET native bundle 提取目录及脚本目录；**未清理 OS 文件缓存、未重启电脑，因此不是严格 OS 冷启动。** 托管入口前的时间包含 runtime、解包、加载和外部扫描，无法仅凭此归因于 Defender。

基线 v3.0.0 源码复制到工作区外，添加只读时间标记及隔离状态路径，保持原窗口和提取行为。原二进制 `/self-test` 首次总体 3459ms，其后 830/984/893ms（含截图/退出，不是首次可见时间）。阶段采样如下：

| 基线采样 | 托管入口 ms | Shown ms | 首次渲染 ms | 状态 ms | 脚本提取+校验 ms |
| --- | ---: | ---: | ---: | ---: | ---: |
| 新 native 提取目录 | 2351.21 | 2788.79 | 2790.46 | 2866.69 | 133.28 |
| 热 1 | 174.04 | 609.67 | 611.06 | 684.36 | 146.26 |
| 热 2 | 185.56 | 667.25 | 669.50 | 758.84 | 156.07 |
| 热 3 | 185.82 | 691.81 | 694.03 | 770.77 | 164.44 |

旧首次绘制通过原 self-test 的 Show/DoEvents/DrawToBitmap 采样；新 benchmark 通过显示真实测试窗口和 WM_PAINT 采样，测试负载不同，不做严格统计显著性声明。完整原始记录保存在 docs/evidence 中。

修复措施：AppController 构造不做 I/O；GUI 首先显示；版本化清单缓存在后台完整校验；只进行一次安全目录遍历；状态/日志读取使用 Task.Run；网络接口名称元数据每分钟刷新；日志最多读取末尾 64KiB/100 条；首次创建控件时批量 Suspend/ResumeLayout；恢复同页时不重排四个页面；重复 EXE 在缓存和引擎创建前激活原窗口。

单文件压缩实验：约 161.9 MB 降至 71.8 MB，但本机实验 Shown 冷 2584.53ms，热 1351.85/1579.37ms；首次实际绘制为 3170.92/1677.12/2038.04ms，私有内存约 88–90MiB。相同设备下没有证明速度收益，因此默认不压缩。未用裁剪、禁用校验或外部运行时降低体积。

优化后四次采样在 `docs/evidence/startup-v31.json` 中记录（采样 EXE SHA256 在报告中；之后文档/证据打包重建会改变 EXE 哈希）。该轮与模拟回归在同一设备运行，可能受到系统负载影响，不是严格 A/B 实验。

| 优化后采样 | Shown ms | 实际绘制 ms | 首次状态 ms | 提取 ms | 完整缓存校验 ms |
| --- | ---: | ---: | ---: | ---: | ---: |
| 新 native/脚本目录 | 655.39 | 1001.52 | 1055.24 | 247.37 | 0.06（尚无缓存） |
| 热 1 | 736.66 | 1028.87 | 1074.24 | 0 | 511.63 |
| 热 2 | 623.78 | 924.45 | 975.02 | 0 | 466.97 |
| 热 3 | 743.55 | 1035.97 | 1101.92 | 0 | 543.57 |

可见窗口不再等待缓存校验；热缓存仍进行完整验证，实际校验在本机约半秒，并没有声称比旧版单次提取更快。托盘恢复与第二 EXE 全过程分开记录，完整数值以原始 JSON 为准。CPU 采样包含定时状态轮询，不能当成静态理论占用或长期平均。

此轮托盘恢复含绘制 103–145ms，第二 EXE 从启动到恢复窗口 390–506ms；5秒闲置/状态刷新窗口 CPU 约 0.30–0.34%（22线程归一化），WorkingSet 116–145MiB，PrivateMemory 50–52MiB。尚无 v3.0 同负载的长期 CPU/内存基线，因此不声称这些指标已经改善。

较早未批量抑制布局时，采样包括 Shown 3158.64ms、实际绘制3249.96ms；一次复制后的测试缓存出现 Access denied 并安全拒绝预热，未跳过校验。保留失败及早期样本在 `docs/evidence/startup-investigation.json`。首次不同二进制的外部扫描、文件缓存、并发负载带来明显波动；不承诺每次冷启动都低于2秒。1–2秒为体验目标，不是硬编码测试门槛。

复现：`powershell.exe -NoProfile -File tools/Measure-Startup.ps1 -Exe release/dist/WiFiProxySwitcher.exe -OutputDirectory artifacts/perf-new -Runs 4`。每轮保存原始阶段数据。重复测试请使用新的目录；已有缓存不等于第一次提取。界面纯托盘打开时间与再次启动完整自包含 EXE 后的时间分开记录，后者仍承担 runtime/外部扫描开销。

官方依据：[.NET 单文件部署](https://learn.microsoft.com/en-us/dotnet/core/deploying/single-file/overview)说明 native 自提取和 DOTNET_BUNDLE_EXTRACT_BASE_DIR；[NotifyIcon](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.notifyicon)描述通知区域及独立菜单交互。
